**Static method** - A named operation that belongs to a class. The Java keyword `static` lets us call this kind of method through the class name, as in `PriceTools.orderTotal(3, 4.5)`. A method can package a calculation so several callers use the same rule. Declaring a method does not run its body; a call requests that work. The word `static` does not promise that the method avoids printing or changing other state.

**Return type** - The part of a method declaration that states the type of value it sends back. A declaration beginning `static double orderTotal` promises a `double` result. The keyword `void` instead declares that the method returns no value. A return type describes the method's result, while parameter types describe its inputs; those types do not have to match.

**Parameter** - A named input variable in a method declaration. In `orderTotal(int quantity, double unitPrice)`, the parameters name the two values the calculation needs and declare their types. The arguments in a call, such as `3` and `4.5`, supply the values for those parameters in order. Each call gets its own parameter variables. Changing a numeric parameter does not change the variable that supplied its value.

**Caller** - The code that requests a method's work by making a call. In `double total = PriceTools.orderTotal(3, 4.5);`, the calling code supplies two arguments and stores the returned number in `total`. Execution continues with the caller after this method finishes normally. The caller can decide to store, print, or use a returned result in another calculation; the method does not have to make that decision for it.

**Return value** - The value a completed method call sends back to its caller. If `orderTotal` returns `quantity * unitPrice`, the call `PriceTools.orderTotal(3, 4.5)` produces `13.5`. That number can become part of a larger expression or be stored in a variable. Returning a number does not display it in the console; printing is a separate operation.

**Return keyword** - Java's `return` statement finishes the current method call. A value-returning method uses a statement such as `return quantity * unitPrice;` to compute and send its result to the caller. A `void` method can use `return;` to finish without a value, or reach the end of its body. In these examples, statements later in the method are not executed after a return; the caller continues instead.

**Void method** - A method whose declared result type is the keyword `void`, meaning it sends no value back. A display method such as `showTotal(9.0)` can print a message and then let the caller continue. We call it as a statement because there is no returned number or string to assign. `void` does not mean that nothing happens, and it does not require the method to print.

**Side effect** - An observable action beyond producing a return value. For example, a method that prints `Total: 9.0` changes what appears in the console. Separating that display action from a price calculation lets the same calculation serve a console report or another interface later. A method can both return a value and have a side effect; its return type alone does not tell us whether it does.

**Pure function** - A calculation whose result depends only on its supplied inputs and that has no observable side effects. The method that returns `quantity * unitPrice` gives the same result for the same input values and leaves display decisions to its caller. This separation makes its input-to-result rule easier to check and reuse. A static method is not automatically pure: printing inside it would add a side effect.

**Pass-by-value** - Java supplies each parameter with a copy of an argument's value. If a caller's numeric variable holds `3`, assigning `quantity = quantity + 1` inside the called method changes that method's parameter to `4`; the caller's variable still holds `3`. The caller must explicitly store a returned result if it wants to replace its own value. This lesson traces numeric values; it does not claim that passing an object creates a separate copy of the whole object.

**Index** - A number that identifies a position in a sequence. Java String positions start at `0`, so the five symbols in `"[red]"` occupy indices `0` through `4`. The first symbol is at index `0`, and the last valid index is one less than `length()`. These examples use ordinary letters and delimiters that each take one position. Java actually counts UTF-16 code units, the pieces used to encode text, so some displayed symbols occupy more than one position.

**charAt method** - The String method that selects the `char` at a supplied index. For example, `"[red]".charAt(0)` selects `'['`. In a loop, changing the index lets the program examine successive positions. Valid indices run from `0` through `length() - 1`; `charAt(length())` asks for a position beyond the text. `charAt` is a method name, not a Java keyword.

**Character value** - A value of Java's primitive type `char`. The keyword `char` declares a variable such as `char symbol = '[';`, which can hold the ordinary delimiter being examined. Comparing it with another character value lets a scan recognize an opening or closing delimiter. A `char` represents one UTF-16 code unit; it does not necessarily hold an entire displayed symbol, and it is distinct from a `String`.

**Delimiter pair** - Two symbols used as an opening and a closing boundary around a section of text. Square brackets form the pair in `"[red]"`, and parentheses form the pair in `"(blue)"`. The method must apply a stated matching rule when pairs appear inside other pairs. A closing symbol by itself does not prove that a valid opening boundary was found earlier.

**Character literal** - A character value written with single quotation marks, such as `'['` or `')'`. The delimiter scanner compares the selected `char` with these literals to recognize a boundary. Double quotation marks instead make a string literal, so `"["` is a String even though it contains one ordinary symbol. Choose the literal form that matches the kind of value being compared.

**Substring range** - A pair of indices that describes a slice of text: the starting position is included and the ending position is excluded. In `"[red]"`, the range from `1` to `4` selects `"red"` and leaves both brackets out. Equal valid bounds select an empty string. The start must be at least `0`, the end must be at most the string length, and the start cannot exceed the end.

**substring method** - The String method that returns the text selected by a range. For example, `"[red]".substring(1, 4)` returns `"red"`. The delimiter method records a start just after the outer opening symbol and uses the matching closing symbol's index as the excluded end. This call does not remove text from the original string. `substring` is a method name, not a Java keyword.

**Nesting depth** - A running count of opening delimiters that have not yet been closed within the section being scanned. An opening bracket increases the depth; a matching closing bracket decreases it. In `"[m[n]p]"`, the inner closing bracket reduces the depth from `2` to `1`, so it does not finish the outer section. Returning to `0` after an active opening identifies the completed outer pair. The supplied method ignores a closing symbol when no opening is active.

**Early return** - A return that finishes a method as soon as the required result is known. The text method returns the substring when a closing delimiter completes the first outer pair, so it does not continue into later pairs. If the scan finds no completed outer pair, a return after the loop supplies an empty string. An early return leaves the whole method; `break` would leave only the loop or switch to which it applies.

**Input and result contract** - A clear statement of what inputs a method accepts and what its results mean. This module's text method accepts a non-null String and extracts the inside of its first completed outer delimiter pair. It ignores unmatched closing symbols before an opening and returns an empty string if no outer pair completes. An empty pair also produces an empty string, so that result alone cannot distinguish empty contents from no completed match. Callers need this rule to interpret the result and choose useful test cases.
