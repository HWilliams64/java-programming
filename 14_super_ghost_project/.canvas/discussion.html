Discussion Topic

Using evidence to finish a complete player

Discussion Prompt

Choose one Super Ghost integration boundary: dictionary move selection, shared binary data, GUI callbacks, or packaged launch. State the actual requirement and describe a test with specific inputs and an expected result. Report one observation from your project, or clearly identify a test you have not yet run. Explain a remaining risk or failure case and the next check that would resolve it. Connect your reasoning to a course example or project milestone.

Context and Purpose

A valid substring does not prove that a move is strategically best, and a responsive window does not prove that every shared-file response follows the arbiter protocol. Use a check suited to the requirement you are discussing.

The supplied project files and arbiter determine the actual interfaces and rule settings. Keep observations separate from assumptions, especially when written rule descriptions leave a boundary unclear. A useful completion record shows both what passed and what remains unresolved.

Requirements and Logistics

  • Identify one integration boundary and its actual requirement.
  • Give specific inputs, expected behavior, and the relevant project milestone.
  • Report an observed result or clearly label an unrun test, then state the next check.
  • Suggest a useful boundary, shutdown, or package test for a classmate without posting a complete team solution.
  • Use clear language and follow the instructor’s posted discussion and submission schedule.
