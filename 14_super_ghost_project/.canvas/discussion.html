Discussion Topic

Using evidence to finish a Super Ghost player

Discussion Prompt

Choose one place where two parts of your Super Ghost player must work together: checking a proposed move against dictionary entries, reading the supplied game records, passing a selection result to the interface, or launching the packaged program. State the project requirement for that connection. Give one ordinary test and one boundary or failure test, with specific inputs and expected results. Report what you actually observed, or clearly label a test you have not run. Explain one remaining issue and the next check that would help resolve it.

Context and Purpose

Your team is preparing a Java player that accepts a letter and a front-or-back placement choice. The supplied arbiter is the separate program that announces turns and checks the game. A useful integration test checks whether cooperating parts agree, such as whether the player can read the arbiter’s game records and display the current fragment correctly.

A passing check of one method does not establish that the whole player works. Connect your reasoning to a project-guide milestone or an earlier course example. Use the supplied project files to identify the actual requirement, and separate results you observed from results you expect. If a rule boundary is unclear, explain what must be checked instead of inventing a rule.

Requirements and Logistics

  • Describe one connection between project parts and the requirement it must satisfy.
  • Give an ordinary case and a boundary or failure case; state inputs, expected results and the relevant project milestone.
  • Record an actual result or identify an unrun test, then explain the remaining issue and next check. Java code is optional.
  • Suggest a precise additional test or ask a useful question about a classmate’s connection. Do not post a complete team solution.
  • Use the accompanying Canvas discussion and follow the instructor’s posted participation requirements and due dates.
