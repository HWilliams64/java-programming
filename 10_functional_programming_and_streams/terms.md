**Functional interface** - An interface whose single abstract method describes one operation that a lambda can provide. For example, `Function` requires an `apply` operation. An interface with two unrelated required abstract operations cannot be implemented by one lambda.
**Function** - A functional interface whose `apply` operation accepts one input and returns a result; its two type arguments describe those types. In `Function<String, String>`, the first type is the input and the second is the returned result. Calling `apply("Ready")` runs the supplied operation; storing the `Function` alone does not.
**Lambda expression** - An expression that supplies parameter-and-body behavior for a compatible functional interface. For `text -> text + "!"`, text is the later input and the body produces the returned `String`. The receiving functional-interface type determines compatibility.
**Behavior as an argument** - Passing a functional-interface value so a method can invoke the supplied rule. A `render` helper can accept both the text and a `Function` that decides how to transform it. The helper invokes `apply` without containing every caller’s formatting rule.
**Captured local value** - A lambda can use an enclosing local value that is `final` or effectively final. Each call to `withPrefix` supplies the value used by its returned rule, even after the method returns. The local variable or parameter must meet Java’s `final` or effectively-final capture rule.
**final** - A Java modifier that prevents reassignment after a variable receives its initial value. For a local variable, assignment of its initial value is allowed but a later reassignment is rejected. A `final` reference does not by itself prevent operations that change the referenced object.
**Effectively final** - A local variable or parameter whose assigned value is not reassigned, allowing its value to be used by a lambda. A method parameter that is not reassigned can be used by the returned lambda without writing `final`. Assignment history matters; reassigning the parameter breaks the rule even if the replacement appears convenient.
**Method reference** - A compact way to supply compatible behavior by referring to an existing method. `String::trim` supplies the existing `trim` behavior for a compatible `Function`. Its eventual `String` input becomes the receiver; the reference does not trim text when created.
**Stream pipeline** - A source and a sequence of operations that describe a computation over collection elements. For example, an ArrayList can supply entries that a pipeline cleans and selects for a report. Intermediate operations describe processing stages, and a terminal operation produces the result. The stream is not a second collection storing a copy of every source entry.
**Intermediate operation** - An operation that adds a processing stage and supplies a stream for the next stage. In these examples, `map` describes a transformation and `filter` describes a selection rule. Intermediate operations alone do not produce the final report list; `toList()` is the terminal operation that starts processing and returns that list.
**Terminal operation** - An operation that initiates a pipeline computation and produces its final result or effect. For example, `toList()` produces the list that the program can inspect afterward. Collecting that result does not itself print the entries; the later enhanced for loop in this lesson performs the printing.
**List** - A Java library interface for an ordered sequence that can contain repeated elements. `List<String>` describes a sequence of String entries; the program can read entries by position, iterate over them, and ask for its size. The type is not a Java keyword. A List variable does not by itself promise that adding, removing, or replacing entries is supported; the particular list determines that behavior.
**Mapping elements** - Applying a function to each processed input element to obtain an output value. For example, `map(String::trim)` supplies cleaned String contents to the next stage. The returned value can differ from the input, but this mapping does not replace an entry in the original source list or modify a String in place.
**Filtering elements** - Using a Boolean rule to decide which processed entries continue to the next stage. For example, `item -> item.length() == 3` keeps an entry when the String it receives has length three. Its position determines whether it tests the original text or a mapped value. The Boolean result controls selection; it does not become a result-list entry, and equal matching entries are not automatically removed.
**Encounter order** - The order that a source defines for its elements. An ArrayList supplies its list order, so the map/filter/toList examples preserve the relative order of retained entries, including repeated matches. These operations do not sort the results. A HashSet source does not provide the same ordering promise.
**Unmodifiable result list** - A result list that allows reading but rejects attempts to add, remove, or replace its entries. The list returned by `toList()` has this restriction: editing it throws `UnsupportedOperationException`. Reading the entries and size is supported. The restriction belongs to the particular result list, rather than to every value declared with the List interface type.
**Lazy evaluation** - Intermediate stream stages describe work before a terminal operation starts processing elements. Storing source.stream().map(...) in pending does not collect a report. The later toList() call produces the completed result; creating a pipeline is not copying source entries.
**Stream** - A Java library type describing elements processed by a pipeline. Stream<String> pending stores the String-processing pipeline in this lesson. It represents a computation rather than an editable collection, and its terminal operation consumes that stream.
**Late-bound collection source** - An ArrayList-backed stream observes its source contents when terminal processing begins. Adding kit after pipeline creation but before toList() therefore includes kit in the report. This does not permit edits during pipeline execution or promise identical binding rules for every stream source.
**Single-use stream** - A stream must not be reused after a terminal operation. After pending.toList(), ask source.stream() for another computation instead of calling pending.count(). The completed report can still be read again without rerunning its pipeline.
**IllegalStateException** - An exception indicating that an operation is invalid for an object’s current state. In the deliberate consumed-stream example, pending.count() fails and the matching catch prints the recovery message. The failed request does not return a numeric count.
**count()** - A terminal stream operation returning the number of elements as a long value. source.stream().count() counts the source with a fresh stream; an empty source produces zero. It neither revives an already consumed stream nor changes an earlier collected report.
**long** - The Java keyword for a primitive whole-number type with a wider range than int. Stream count() returns long even when its value is printed directly rather than stored. No conversion to int is required merely to display the count.
**UnsupportedOperationException** - An exception indicating that the particular object does not support the requested operation. Adding to the unmodifiable toList() result fails with this type, while later reading its size is allowed. It identifies an unsupported result edit, a different issue from reusing a consumed stream.
**Collection copy** - A new collection initialized with another collection’s current elements. new ArrayList<String>(report) creates a separate editable list structure in the same order. Adding an entry to this copy does not add it to the source or report; assigning another reference to report would not create that structure.
**Shallow copy** - A copy with separate collection structure but references to the same element objects. The report and its new ArrayList initially reference the same String elements; editing membership affects only the chosen list. This constructor does not clone element objects, and immutable Strings cannot be changed in place.
**Reduction** - An operation that combines processed values into one result. A report can use it to turn delivery quantities into a total rather than collecting another list. For example, `counts.stream().reduce(0, (left, right) -> left + right)` returns the sum using zero and addition. This terminal operation consumes its stream and returns a value; it does not require the lambda to update a separate shared total. A new computation needs a fresh stream. The result is only meaningful when the identity and combining rule satisfy the operation's contract.

**BinaryOperator** - A functional interface whose operation accepts two values and returns a value of the same type. A `BinaryOperator<Integer>` can store `(left, right) -> left + right`, and `apply(3, 5)` invokes that rule to produce eight. The lambda returns a combined value instead of assigning into its inputs or a shared accumulator. In a reduction, an input may represent a source contribution or a partial result. The interface's type shape alone does not guarantee that a rule is associative or has a valid identity; subtraction also fits that type shape but fails the grouping requirement.

**Identity value** - A neutral value for a combining rule. Combining it with an input leaves the input unchanged, and an identity-based reduction returns it when there are no contributions. Zero works for addition: both `0 + 6` and `6 + 0` produce six. Starting a sum at one invents an extra contribution and does not satisfy the identity requirement. The identity is part of the operation, while a zero stored in a list is an actual source entry; they can have the same numeric value but different roles.

**Associative combination** - A combining rule that gives the same result when the same ordered inputs are grouped differently. With the lesson's small integers, `(2 + 4) + 1` and `2 + (4 + 1)` both produce seven. That allows valid partial sums to be combined into the same result. Subtraction fails this check: `(8 - 3) - 1` produces four, while `8 - (3 - 1)` produces six. Regrouping is different from reordering inputs, and a neutral identity does not establish associativity by itself. Other number types require their own reasoning about grouping and precision.

**Parallel stream processing** - A requested execution mode in which Java may divide pipeline work into parts that can run at the same time and combine their partial results. A collection's `parallelStream()` requests that mode. Correct identity and associative combination rules allow a reduction to account for all contributions without depending on one particular grouping. The request does not promise a worker count, an element-processing schedule, or a speed improvement. Two printed totals show returned results; they do not measure performance or reveal each worker's actions.

**Stateless behavior** - A processing rule that does not depend on changing state shared between its calls. The mapping `value -> value + 1` returns its result from the supplied value, so processing a different entry first does not change that rule's answer. A lambda that reads and updates a shared running total has a different dependency and may produce incorrect parallel behavior. Putting that total inside a mutable array or object does not remove the dependency. An unchanged captured reference does not make the referenced object's changing state safe to share.

**Noninterference** - Leaving the stream's source unchanged while its pipeline executes. A mapping can return a new computed value without assigning it into the source list. In contrast, adding an entry to `counts` from inside a pipeline processing `counts` changes the very source being traversed. Noninterference concerns the source; statelessness concerns dependencies on changing state between calls. Keeping the source unchanged is necessary even when the rule does not use any separate shared counter.
