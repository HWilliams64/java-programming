Module 07 Overview: Exceptions and Testing

CSC-239 Java Programming

Overview

A reservation or equipment system must respond clearly when a request cannot be completed. This module traces how Java exceptions interrupt work and how a caller can handle a failure. You will state failure contracts, preserve useful causes, and release resources when work ends. You will finish by writing automated JUnit checks for ordinary inputs, boundaries, and required exceptions, then confirm that those checks detect a deliberate mismatch.

Key Concepts

  • Exception control flow: trace interrupted work and matching handlers.
  • Failure contracts: distinguish throwing, declaring, and preserving a cause.
  • Resource cleanup: release acquired resources and retain the primary failure.
  • JUnit tests: compare normal, boundary, and failure behavior with explicit expectations.
  • Test reliability: distinguish a deliberate assertion mismatch from a regression caused by an application change.

Outcomes

Upon completion of this module, students will be able to:

  • Place handlers so independent later inputs can still be processed.
  • Design clear checked exception contracts and preserve causes.
  • Release resources on success and failure.
  • Write and run meaningful JUnit tests for normal, boundary and exception behavior.

Guiding Questions

Consider the following questions as you review the learning resources this week:

  • Which work should continue after a failed request, and where should the handler belong?
  • What information should an operation preserve when it reports a failure?
  • How can a test demonstrate both correct behavior and its ability to detect an error?
