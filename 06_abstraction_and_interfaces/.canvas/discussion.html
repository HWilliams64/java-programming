Shared promises and different implementations

Discussion Topic

Shared promises and different implementations

Discussion Prompt

Choose two real-world services, tools, or roles that can answer the same request in different ways. State the shared promise and describe what each implementation does. Explain what the caller needs to know and what details can stay hidden. Then identify one behavior that could be shared and one that must remain different. Connect your design to an interface or abstract-class example from the module.

Context and Purpose

A room sign and a course sign can both provide a label, even though they store different information. Different work items can share a name and description while calculating their time in different ways.

Use the shared promise to judge your design. An implementation should still meet that promise when a caller refers to it through the shared type. A real-world analogy helps, but explain its limits when it differs from Java.

Requirements and Logistics

  • Describe two implementations and a clear shared operation.
  • Connect the design to a named module interface, default method, or abstract class.
  • Explain hidden details, shared behavior, and behavior that must differ; code is optional.
  • Test a classmate’s shared promise with a new request or propose a useful clarification.
  • Use the accompanying Canvas discussion and follow the instructor’s posted participation requirements and due dates.
